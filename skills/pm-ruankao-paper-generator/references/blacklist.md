# 内容合规黑名单（步骤六验证时读取）

> 验证时逐项检查论文中是否出现以下内容。**只有当用户明确说明项目是政府/信创类型时**，才允许使用对应元素。

## 1. 场景类型禁止项

- "甲方/乙方"、"中标了某某项目"、"我单位作为乙方"等外部承接项目话术（默认是企业内部数字化项目）
- "智慧水务/数字政务/智慧城市/工业互联网"等政府或大型集团项目类型
- "等保三级/国密算法/政务云"等政府合规背景

## 2. 技术栈禁止项

- "麒麟OS/达梦数据库/东方通中间件/鲲鹏服务器/人大金仓"等信创国产化技术栈
- "UiPath/Automation Anywhere/Blue Prism"等海外 RPA（实际栈是影刀 RPA）
- "Kafka/ClickHouse/Airflow/Apache Superset/RabbitMQ"等未实际使用的栈（实际数据栈是 Doris + DolphinScheduler；Pandas 属于实际栈，不在禁用范围）

## 3. 角色表述禁止项

- "IT经理（兼IT总监）/ IT经理（IT总监）"等重复或层级不清的表述（角色是 IT 总监）
- "我作为甲方项目经理 / 我作为乙方项目经理 / 我作为公司 CTO 兼 IT 总监"——应写成"作为公司 IT 总监同时担任本项目的项目经理"

## 4. 项目边界禁止项

- "双轮驱动/自下而上+自上而下/先支撑业务后引领业务/敏捷开发，业务驱动"等项目集层级叙事（会把单项目写成项目集）
- "ERP项目"+"钉钉金蝶项目"+"积加金蝶项目"等并列罗列（应写成同一项目下的业务条线/子模块）
- "双团队/两个团队/两支团队"（应写成"项目团队下设两个职能小组"）
- 把"业财一体化"写成"项目集/多个并列子项目集合"

## 5. 术语与图表禁止项

- 直接堆砌 PMBOK 英文术语（Stakeholder Engagement Matrix、Power/Interest Grid 等）；优先软考第四版中文术语
- RACI 责任分配矩阵作为主图表（软考高项极少考，可点一笔但不要主推）

# 软考高项论文生成器

## 任务目标

本 Skill 用于生成符合软考高级项目经理考试论文评分标准的完整论文，核心能力包括：

1. **四段式结构生成**：按「背景→过渡→正文→收尾」生成符合规范的论文
2. **十大管理 + 八大绩效域适配**：灵活适配十大管理主题和八大绩效域主题（干系人/团队/规划/度量/开发方法和生命周期/工作/交付/不确定性）
3. **踩分点精准覆盖**：确保项目真实性、大型复杂项目特征、数字化转型立意、首尾呼应
4. **固定逻辑+可变内容分离**：提供可复用的模板框架，降低多主题备考工作量
5. **绩效域融合写作**：支持"绩效域×十大管理×量化指标"三维融合论文生成

## 触发条件

当用户有以下需求时，调用本 Skill：

- "帮我生成一篇XX管理主题的软考论文"
- "请按照软考标准写一篇信息系统项目管理论文"
- "给我一个软考论文模板"
- "优化我写的软考论文"
- "软考论文的背景怎么写"
- "帮我生成一篇XX绩效域的软考论文"
- "请写一篇干系人绩效域/规划绩效域/团队绩效域的论文"
- "绩效域论文怎么写"

## 前置准备

用户需提供以下信息：

| 信息类型 | 必填 | 说明 |
|---------|------|------|
| 论文主题 | 是 | 十大管理领域之一（整合/范围/进度/成本/质量/资源/沟通/风险/采购/干系人）或八大绩效域之一（干系人/团队/规划/度量/开发方法和生命周期/工作/交付/不确定性） |
| 主题类型 | 是 | "十大管理" 或 "绩效域"，决定论文正文结构（过程组式 vs 绩效要点式） |
| 项目名称 | 是 | 真实或模拟的项目名称（默认场景：业财一体化信息系统建设项目） |
| 项目类型 | 是 | 企业内部数字化建设项目，如：业财一体化、ERP 集成、BI 数据平台、RPA+AI 自动化、智能决策系统、跨境电商中台等 |
| 发起方 | 是 | 公司董事会 / 集团总部 / 业务部门（默认是公司内部立项，非外部甲方） |
| 投资金额 | 是 | 项目总投资额（参考量级：300万–2000万） |
| 工期 | 是 | 项目周期（参考：12–24 个月） |
| 项目组织结构 | 是 | 矩阵型 / 项目型（默认：公司 IT 部门内部组建项目组，矩阵型为主） |
| 项目特点 | 是 | 大型复杂项目的特征（多系统集成、多业务模块、多干系人协同、跨部门跨地区等） |
| 技术栈 | 建议提供 | 实际使用的技术栈（默认：Spring Boot 2.7 / MyBatis-Plus / MySQL 8 / Redis / Vue 3 / Element Plus / ECharts / Python + FastAPI / Pandas / Doris / DolphinScheduler / Nginx / Docker / 影刀 RPA / Playwright / 积加 ERP / 马帮 ERP / 金蝶云星空 / 钉钉 / 飞书 / GitLab 等） |
| 个人角色 | 是 | 默认：作为公司 IT 总监，同时担任本项目的项目经理，全面负责项目全生命周期管理 |

> **重要约束**：本技能默认服务于"跨境电商企业内部数字化项目"场景，场景一致性、技术栈、角色表述、项目边界等合规检查详见 `references/blacklist.md`（步骤六验证时必读）。

> **业财一体化建设期项目（论文默认场景，单一项目边界）**：
>
> 论文默认以"**XX 跨境电商集团业财一体化建设期项目**"为载体（预算 1300 万元、工期 24 个月、单一项目章程、单一项目经理）。**避免写成项目集**——所有交付物都属于同一项目章程下的范围基准，按"两条业务条线 + 分阶段交付"统一规划。
>
> | 业务条线 | 承载团队 | 范围（同一 WBS 下的工作包） |
> |---------|---------|---------------------------|
> | **① 业务系统条线**（核心是供应链一体化） | 业务系统组（4 人） | 自研 ERP1.0：覆盖**供应链业务流**，含产品、采购、仓库、物流、销售、计划、财务、统计、首页、运营工具、工具、系统等 12 个主模块、28 个业务版块、约 91 个 Sprint 子功能（跨 Sprint 21–45 滚动迭代） |
> | **② 财务集成条线** | 数据效能组（4 人） | 金蝶云星空集成模块（OA 钉钉审批 → 金蝶应收单链路、积加 ERP 利润报表 → 金蝶应收单链路、利润报表系统、发票智能识别等具体集成功能）；以**模块**形式纳入项目范围，与业务系统条线对齐里程碑 |
>
> **交付节奏（同一项目内的分阶段交付，不是两个并列项目）**：
> - **阶段一（M1–M9）**：业务需求引导 + 财务集成条线优先交付（钉钉金蝶 v1.0、积加金蝶 v1.0、利润报表 v1.0），先打通业务痛点
> - **阶段二（M10–M20）**：业务系统条线主线开发（ERP 12 主模块滚动 Sprint 迭代），同时财务集成条线持续优化
> - **阶段三（M21–M24）**：联调、UAT、上线、运维移交
>
> ⚠️ **重要：项目 vs 项目集边界约束**——软考论文必须以**单一项目**为载体，**不要**把"业财一体化"写成多个并列子项目的项目集：
> - ❌ 不写"双轮驱动 / 两条主线 / 自下而上 + 自上而下 / 先支撑业务后引领业务"——这是公司项目集层级方法论，单项目用不上
> - ❌ 不写"ERP 项目"+"钉钉金蝶项目"+"积加金蝶项目"+"利润报表项目"等并列罗列——会让评委觉得是项目集
> - ✅ 写"两条**业务条线**"（条线是同一项目内的范围划分）或"两个**子模块/建设阶段**"
> - ✅ 写"分阶段交付"或"滚动迭代"——单项目内合理的交付策略
> - ✅ ERP 主体内容贴近**供应链业务流**（这是真实定位），不要泛化为"ERP 整个平台"
>
> **公司层面的兄弟项目**（**仅供论文背景中作为"集团数字化战略组合"一笔带过**，不并入本论文项目章程）：BI 数据平台、RPA 全员推进、智能决策系统等。

## 操作步骤

### 步骤一：信息确认与主题锁定

1. 明确论文主题：询问用户具体管理领域或绩效域，确认主题类型：
   - **十大管理**：确认所涉及的详细过程组（通常4-6个过程）
   - **绩效域**：确认绩效域名称及其绩效要点数量，读取 `references/performance-domains.md` 获取绩效要点、预期目标和检查方法
2. 收集项目信息：按前置准备表格逐项确认
3. 锁定大型复杂特征：明确项目是否涉及跨系统对接、多模块集成、多干系人协同
4. **确认额外写作要求（关键步骤）**：主动询问用户是否有特殊的论文写作要求，包括但不限于：
   - **主题交叉关系**：是否需要分析本管理主题与其他管理主题的关系（如进度管理对成本/质量的影响）
   - **重点分析内容**：是否有指定需要重点论述的内容（如某过程的重要性、与其他领域的协同等）
   - **图表展示需求**：是否需要使用图表形式展示ITTO工具技术以增强项目真实性（如甘特图、里程碑清单、WBS分解图、风险概率影响矩阵等）
   - **字数分配偏好**：各段落是否有特定的字数要求或侧重点

   **示例提问方式**：
   > "请问除了基本的论文结构外，是否有以下特殊要求：
   > 1. 是否需要重点分析【XX管理】对【其他管理领域】的影响或交叉关系？
   > 2. 正文中是否有指定的重点论述内容、论述过程组或论述的过程组所使用的工具和技术？
   > 3. 是否需要使用图表（如甘特图、里程碑图、WBS结构图等）来增强项目论述的真实性和可读性？
   > 4. 其他特殊论述要求和论述点？"

   **交叉主题处理规范**：
   如用户提出需要分析与其他管理领域的关系（如"进度管理对成本的影响"），必须明确记录：
   - 交叉主题：如成本管理、质量管理等
   - 关联过程：确定在本主题哪些过程中自然融入（如进度管理的"制定进度计划"过程融入成本分析）
   - 融入方式：在对应过程的"工具/方法应用"或"效果与价值"段落中自然体现
   - **重要**：严禁在正文外单独增加段落论述交叉主题

### 步骤二：背景段落生成（400-520字）

按「两段式结构」生成背景：

**第一段（约150-200字）：行业背景与战略动因→项目基础信息→角色权责**

固定逻辑（**默认场景：跨境电商企业内部数字化项目**）：
- 战略动因句（推荐范式）：随着公司跨境电商业务规模快速扩张，多套异构业务系统数据割裂导致月结周期长、利润核算偏差大，集团董事会基于"数字化转型"和"业财一体化"战略，决策立项启动 XX 项目。
  - 备选政策依据（不强制）：可在战略动因中点一句"贯彻《"十四五"数字经济发展规划》、响应国家数字化转型导向"，作为立意拔高，但不要堆叠政府文件。
- 角色句（**核心模板**，简洁、谦和，但需点出"项目战略级"以解释 IT 总监为何亲自担任项目经理）：
  - 作为公司 IT 总监并担任本项目的项目经理，我全面负责项目全生命周期管理；项目采用矩阵型组织结构，由 IT 部门内部组建单一项目团队承载。
  - ⚠️ **禁止表达**：「IT 经理（兼 IT 总监）」、「我作为甲方/乙方项目经理」、「我作为公司 CTO 兼 IT 总监」——身份必须清晰、单一。

**第二段（约250-320字）：项目目标→建设内容（含技术栈）→管理难点铺垫**

固定逻辑：
- 总述：本项目核心目标是 XXX（如打通业财数据链路、实现月结由 7 天压缩至 2 天等可量化目标），解决 XXX 业务痛点
- 建设内容：按"业务架构 + 技术架构"两条线展开，**技术栈使用公司实际栈**（参考默认栈：Spring Boot 2.7 / MyBatis-Plus / MySQL 8 / Redis / Vue 3 / Element Plus / ECharts / Python + FastAPI / Pandas / Doris / DolphinScheduler / Nginx / Docker / 影刀 RPA / Playwright / 积加 ERP / 马帮 ERP / 金蝶云星空 / 钉钉 / 飞书 / GitLab）
- 管理难点铺垫：呼应论文主题，为后续正文铺垫管理难点（多系统集成、需求变更频繁、跨部门协同、人员快速扩张等）

生成要点：
- 必须包含：可量化业务目标、真实技术栈、大型复杂项目特征（多系统集成 / 多模块 / 多干系人）
- **严禁**默认堆砌"麒麟OS / 达梦数据库 / 等保三级"等不属于用户实际技术栈的元素
- 字数控制：400-520字，两段比例约 1:2
- **技术栈精简原则**：第二段技术栈用一句概括即可（如"技术栈采用Spring Cloud微服务架构、Vue 3前端、Python+FastAPI数据接口、Doris数据仓库、影刀RPA等"），避免逐一罗列每个框架版本号，防止背景段超520字

### 步骤三：过渡段落生成（170-270字）

按「难点切入 → 主题点题 → 简短进展 → 论文预告」结构生成。

> ⚠️ **过渡段必须独立成段，严禁混入背景段**。6篇A级论文验证：过渡段独立为"## 二、过渡段"，与背景（## 一）明确分隔。

> ⚠️ **过渡段与收尾段严禁开头雷同**：
> - **过渡段**禁止以"截至 XXXX 年 XX 月，本项目已按里程碑顺利推进至 Sprint XX，完成 1305/1762 项工作项..."开头——这是收尾段的写法
> - **过渡段**应从"项目难点"或"管理领域必要性"切入，将"项目阶段性进展"压缩为一句话点缀，并把**详细数据/可交付物清单**留给收尾段

固定逻辑：
1. **难点切入**（约80-120字）：作为涉及 4 套异构系统集成、12 个主模块、20 余位跨部门干系人协同的大型复杂信息系统项目，本项目面临跨系统集成难度大、需求变更频繁、两个职能小组（业务系统组与数据效能组）协作存在断点等核心难点，各管理领域相互依赖制约
2. **主题点题**（约15-20字）：科学规范的项目 XX 管理成为确保项目成功的关键
3. **简短进展**（**仅一句话**，约20字，不堆砌数据）：项目目前已稳步推进至 Sprint 21，关键可交付物按里程碑陆续上线
4. **论文预告**（约40-60字）：本文以本项目为实践载体，围绕项目 XX 管理的核心过程，阐述实践中的成功经验、存在的不足及改进措施

生成要点：
- 必须明确论文主题
- 必须预告正文核心内容
- **不要**在过渡段中列举"完成 X 项工作项 / 财务月结 7→2 天 / T+1→T+0 / 多店铺自动化"等详细量化数据（这些留给收尾段）
- **难点切入要呼应论文主题**：不同管理主题应有不同的难点描述，避免所有论文用完全相同的过渡段

### 步骤四：正文段落生成（每个过程200-400字左右，根据论文要求调整）

**根据步骤一确认的主题类型，选择对应的正文结构：**

- **十大管理** → 执行 [4A：过程组式正文](#4a-十大管理过程组式正文)（四段式：定义→场景→工具→效果）
- **绩效域** → 执行 [4B：绩效要点式正文](#4b-绩效域绩效要点式正文)（绩效要点→预期目标→协同关系）

#### 4A：十大管理·过程组式正文

根据论文主题，确定涉及的过程组（通常4-6个），每个过程按「四段式结构」生成：

1. **定义与作用（开篇1句）**：一句话点明该过程的核心定义，以及对大型复杂项目的价值
2. **项目场景落地（中间1-2句）**：结合项目背景，说明该过程的具体应用场景，体现大型复杂项目特殊性
3. **工具/方法应用（核心1-2句）**：采用的具体工具、方法、流程（如CCB、挣值分析、WBS等）
4. **效果与价值（收尾1句）**：该过程的实施对项目带来的实际效果

**十大管理领域常用过程参考**：

| 管理领域 | 常用过程 |
|---------|---------|
| 整合管理 | 制定项目章程、制定项目管理计划、指导与管理项目工作、监控项目工作、实施整体变更控制、结束项目或阶段 |
| 范围管理 | 规划范围管理、收集需求、定义范围、创建WBS、确认范围、控制范围 |
| 进度管理 | 规划进度管理、定义活动、排列活动顺序、估算活动持续时间、制定进度计划、控制进度 |
| 成本管理 | 规划成本管理、估算成本、制定预算、控制成本 |
| 质量管理 | 规划质量管理、管理质量、控制质量 |
| 资源管理 | 规划资源管理、估算活动资源、获取资源、建设团队、管理团队、控制资源 |
| 沟通管理 | 规划沟通管理、管理沟通、监督沟通 |
| 风险管理 | 规划风险管理、识别风险、实施定性风险分析、实施定量风险分析、规划风险应对、实施风险应对、监督风险 |
| 采购管理 | 规划采购管理、实施采购、控制采购 |
| 干系人管理 | 识别干系人、规划干系人参与、管理干系人参与、监督干系人参与 |

生成要点：
- 每个过程严格遵循四段式结构
- 必须体现具体工具/方法（软考第四版考点，优先使用中文术语）
- 必须贴合项目实际场景
- 必须体现对大型复杂项目的特殊价值
- **主题交叉关系处理**：如用户要求分析与其他管理领域的关系，**必须在对应过程中自然融入**，严禁单独另起段落。例如：
  - 进度管理论文中分析进度压缩对成本的影响 → 在"制定进度计划"过程的"工具/方法应用"段落中融入
  - 成本管理论文中分析成本超支对进度的反作用 → 在"控制成本"过程的"效果与价值"段落中融入
  - 质量管理论文中说明质量标准对进度的约束 → 在"规划质量管理"过程的"项目场景落地"段落中融入

---

#### 4B：绩效域·绩效要点式正文

绩效域论文的正文结构与十大管理**完全不同**，不按"过程组四段式"展开，而是按"绩效要点"展开，并包含预期目标检查和协同关系分析。

**读取参考**：执行前必须读取 `references/performance-domains.md` 获取对应绩效域的绩效要点、预期目标、检查方法和写作思路。

**正文结构（按以下模块组织）：**

##### 模块一：绩效要点展开（核心部分，约1200-1800字）

根据绩效域的绩效要点数量（通常3-8个），**每个绩效要点按以下结构生成**：

1. **要点阐述（1-2句）**：说明该绩效要点的定义和核心内容
2. **项目场景落地（2-3句）**：结合项目背景，描述在该要点上的具体实践
3. **工具/方法应用（1-2句）**：使用的具体工具或方法（如权力利益方格、度量仪表盘等）
4. **效果评估（1句）**：该要点实施后的实际效果

> **写作节奏控制**：绩效要点较多时（如规划绩效域8个要点），可将相近要点合并论述，不必每个单独成节。建议控制在5-8个段落内。

##### 模块二：预期目标及检查方法（约300-500字）

1. **列出预期目标**：逐条列出该绩效域的预期目标（参考 `references/performance-domains.md`）
2. **说明检查方法**：每条预期目标对应的检查方法/指标
3. **项目实践对应**：在项目中如何通过检查方法验证预期目标的达成

##### 模块三：与其他绩效域的协同关系（约300-500字，视题目要求）

近年命题趋势要求分析绩效域之间的协同关系，如题目有此要求则必须包含：

1. **协同关系表**：用Markdown表格列出本绩效域与其他绩效域的相互作用
2. **重点协同说明**：选择2-3个关联最紧密的绩效域，详细说明协同机制
3. **项目实践融入**：在项目中如何利用协同关系提升管理效果

**绩效域正文结构示例（以干系人绩效域为例）：**

```
背景500字 → 过渡段200字
→ 一、识别干系人（绩效要点1，约300字）
→ 二、理解和分析干系人（绩效要点2，约300字）
→ 三、干系人优先级排序（绩效要点3，约200字）
→ 四、促进干系人参与（绩效要点4，约300字）
→ 五、监督干系人参与（绩效要点5，约200字）
→ 六、预期目标及检查方法（约300字）
→ [可选] 七、与其他绩效域协同（约400字）
→ 收尾300字
```

**绩效域论文常用图表：**

| 绩效域 | 推荐图表 |
|--------|---------|
| 干系人绩效域 | 干系人权力/利益方格、干系人参与度评估矩阵（画两次） |
| 团队绩效域 | 团队发展阶段图（塔克曼五阶段）、共享责任结构表 |
| 规划绩效域 | 项目管理计划组成图、各子计划关联表 |
| 度量绩效域 | 度量指标仪表盘、控制图 |
| 开发方法和生命周期绩效域 | 生命周期阶段与交付节奏对应表 |
| 工作绩效域 | 绩效要点与管理领域对应表 |
| 交付绩效域 | 五大过程组与交付绩效协同表 |
| 不确定性绩效域 | 不确定性四层面应对表、绩效域协同关系表 |

生成要点：
- 每个绩效要点严格遵循"阐述→场景→工具→效果"结构
- 预期目标必须与教程原文一致（理论默写部分）
- 协同关系部分可画表格，言之成理即可
- **融合写作**：如题目要求结合十大管理，在对应绩效要点的"工具/方法应用"中自然融入

### 步骤五：收尾段落生成（200-300字）

按「项目复盘→经验总结→不足改进→未来展望」结构生成：

固定逻辑（**默认企业内部项目场景**）：
1. 复盘（约60-80字）：截至XXXX年XX月，本项目已按里程碑顺利推进至Sprint XX，完成XXX项工作项，关键可交付物已上线，财务月结从7天压缩至2天等量化指标达成预期
2. 经验总结（约50-70字）：项目成功离不开科学规范的项目XX管理体系的落地，通过具体机制有效应对了核心难点
3. 不足与改进（约50-80字）：项目实施中仍存在不足，如初期对XX预判不足，后续通过XX机制及时纠偏
4. 未来展望（约30-40字）：未来我将持续深化业财一体化与数字化转型实践，为公司数字化战略贡献力量

> ⚠️ **收尾段写作红线（6篇A级论文验证）**：
> - ❌ **禁止"深刻认识到"感悟段**：如"通过这一实践，我深刻认识到XX的重要性"——不是得分点，纯浪费字数，必须删除
> - ❌ **禁止哲学式开头**：如"项目管理是一门艺术，更是一门科学"——与企业内部项目语境不符，直接从项目复盘开始
> - ❌ **禁止罗列过多不足**：只写1-2个真实具体的不足即可，避免变成自我批评
> - ✅ **复盘数据一次性给完**：Sprint进度、工作项完成数、月结压缩等数据集中在收尾段给出，不要分散在过渡段

生成要点：
- 必须首尾呼应（呼应开篇背景和正文主题）
- 必须体现真实具体的不足和改进措施
- 必须积极向上，贴合公司数字化转型 / 业财一体化方向（**禁止**生硬使用"为国家信息化建设贡献力量"等与企业内部项目语境不符的话术）
- 字数严格控制：200-300字，超过300字会挤压正文字数空间

### 步骤六：强制验证与质量检查（关键步骤）

**⚠️ 重要：此步骤为强制流程，必须完整执行并通过后才能向用户展示论文**

生成完成后，必须执行以下检查，**任一检查项不通过都必须返回重新生成**：

#### 6.1 字数合规检查

**2025年考试新标准（2000-3500字），软考字数规则：图表不计入字数统计。**

| 部分 | 字数要求 | 说明 |
|------|---------|------|
| 背景 | 400-520字 | 含项目背景+建设内容，不含过渡内容 |
| 过渡段 | 170-270字 | **必须独立成段**，不混入背景 |
| 正文（十大管理） | 每个过程200-400字 | 重点过程可400字，其他200-300字 |
| 正文（绩效域） | 绩效要点1200-1800字 + 预期目标250-400字 + 协同关系200-350字 | 绩效域论文三项必写 |
| 收尾 | 200-300字 | 必须含不足+改进方向 |
| **总字数** | **2000-3500字** | 图表不计入；目标2800-3400字为最佳区间 |
| **图表数量** | **2-3张** | 考场画表时间≤15分钟，超过3张写不完 |

**处理规则**：如字数超出或不足，必须调整对应段落内容后重新生成。

#### 6.2 格式规范检查
- ✅ 四段式结构完整：背景、过渡、正文、收尾
- ✅ 十大管理论文：正文按过程组展开（4-6个过程），每个过程遵循"定义与作用→项目场景落地→工具/方法应用→效果与价值"
- ✅ 绩效域论文：正文按绩效要点展开（3-8个要点），包含预期目标及检查方法模块，可选包含协同关系模块
- ✅ 段落标识清晰：背景段、过渡段、正文段（1、2、3...）、收尾段
- ✅ 无Markdown格式错误：表格格式正确、无断裂行

**处理规则**：如格式有误，必须修正格式后重新生成。

#### 6.3 内容合规检查
- ✅ **伦理合规**：无违反职业道德的内容，无不实夸大，无敏感信息泄露
- ✅ **项目真实性**：有明确的发起方、投资、工期、技术栈，数据合理可信
- ✅ **理论与实践结合**：每个过程有理论定义+具体工具+项目场景
- ✅ **大型复杂项目特征**：多模块/跨系统/多干系人
- ✅ **首尾呼应**：收尾呼应开篇背景和正文主题
- ✅ **场景一致性**：读取 `references/blacklist.md`，逐项检查论文中是否出现禁止元素

**处理规则**：如存在伦理或合规问题，必须修改对应内容后重新生成。

#### 6.4 逻辑闭环检查
- ✅ 背景铺垫的管理难点与正文各过程对应
- ✅ 各过程之间逻辑连贯，无跳跃或重复。
- ✅ 收尾总结与正文论述一致

**处理规则**：如逻辑不闭环，必须调整逻辑后重新生成。

#### 6.5 主题一致性检查
- ✅ **十大管理论文**：全文围绕单一核心管理主题展开，且该主题下每一个管理过程不可缺少（可根据要求详略分配）
- ✅ **绩效域论文**：全文围绕单一绩效域展开，绩效要点覆盖完整，预期目标及检查方法必须包含，协同关系部分视题目要求
- ✅ 未同等混合其他核心管理主题或绩效域

**处理规则**：如主题分散，必须聚焦主题后重新生成。

#### 6.6 特殊要求合规检查（如用户在步骤一提出）
- ✅ **主题交叉关系**：如要求分析对成本/质量的影响，检查是否在本主题相关过程中自然融入（**禁止单独另起独立段落**）
- ✅ **重点内容突出**：检查指定的重点内容是否充分展开
- ✅ **图表展示**：如需表格，确保在对应过程段落中以Markdown表格形式提供

**处理规则**：
- 如交叉主题影响分析未在正文过程中自然融入（而是单独成段），必须重新编排段落结构
- 如其他特殊要求未满足，必须补充后重新生成

#### 6.7 验证结果处理

**全部检查通过后**：向用户展示完整论文

**任一检查未通过**：
1. 标注具体问题位置
2. 说明不符合项
3. 返回对应步骤修改后重新生成
4. 重新生成后必须再次执行步骤六完整检查

**禁止行为**：
- ❌ 未通过检查即向用户展示论文
- ❌ 仅口头提示问题但不修改
- ❌ 降低检查标准通过

## 注意事项

1. **项目真实性**：必须使用真实可信的项目信息，避免使用明显虚构的数据（如投资金额过小、工期不合理等）
2. **场景一致性**：技术栈和项目场景与用户实际一致，具体禁止项见 `references/blacklist.md`。可改用"国产 SaaS（金蝶云星空 / 钉钉 / 飞书 / 积加 ERP / 影刀 RPA）"等贴合企业实际的"自主可控"叙事，自然体现数字化转型立意。
3. **角色定位**：写"作为公司 IT 总监并担任本项目的项目经理，我全面负责项目全生命周期管理"——具体禁止表述见 `references/blacklist.md`。
4. **大型复杂特征**：在背景、正文各环节，强调多模块集成、多系统对接、跨部门干系人协同等特征
5. **工具方法具体化**：避免泛泛而谈，必须写出具体工具名称（如挣值管理中的PV/EV/AC、CCB、WBS词典等）
6. **不足与改进真实化**：不足必须是真实、具体的，改进措施必须有针对性
7. **核心主题单一性**：全文围绕单一核心管理主题展开，不要在一个论文中同等混合多个核心管理主题。可以围绕论文核心主题，进行阐述其他项目管理主题预置的相关性内容和管理关系。
8. **考试实用性**：生成的论文应便于用户背诵和临场发挥，保持语言流畅、逻辑清晰
9. **主题交叉关系处理（严格规范）**：
   - **基本原则**：全文必须围绕单一核心管理主题展开
   - **交叉分析位置**：如用户要求分析本主题与其他管理领域的关系，**必须在正文相关过程中自然融入**，如：
     - 在进度管理的"制定进度计划"过程中提及进度压缩对成本的影响
     - 在成本管理的"控制成本"过程中分析成本超支对进度的反作用
     - 在质量管理的"规划质量管理"过程中说明质量标准对进度的约束
   - **禁止行为**：
     - ❌ **严禁单独另起一个独立段落**专门论述其他管理主题
     - ❌ 严禁在正文外增加"对其他管理主题的影响分析"等独立章节
     - ❌ 严禁将交叉分析放在过渡段或收尾段大篇幅展开
   - **正确示例**：
     > "在制定进度计划过程中，我充分考虑了成本约束因素。通过关键路径分析识别出核心模块开发为关键活动，若采用快速跟进压缩进度可能导致返工成本增加15%，因此我采用资源平衡策略，在关键活动上增派2名高级开发人员，既保证了进度目标，又将成本控制在预算范围内。"
   - **错误示例**：
     > ❌ "【独立段落】进度管理对成本管理的影响分析：进度延误会导致成本增加，因为人力成本按时间计算..."
10. **图表展示方式**：软考论文备考资料中可使用**Markdown表格**和**Mermaid图表**两种形式呈现。考试时需用机考画板工具手工还原。

   - **常考图表优先**：软考高项论文 **重点考察 WBS 分解表、需求跟踪矩阵（RTM）、权力利益方格、干系人参与度评估矩阵、挣值分析表（PV/EV/AC/SPI/CPI/EAC）、S 曲线、甘特图、网络图（CPM 关键路径）、风险登记册（含概率影响矩阵）、绩效域协同表**等。
   - **Markdown表格**：适用于结构化数据展示（WBS分解表、需求跟踪矩阵、挣值分析表、风险登记册、干系人矩阵等）
